# StepFund 使用指南

版本 0.6.0 · 合约协议 v3 · 2026-10-03

面向接收软件的人。界面可切换中英文；本指南使用中文说明，并标注关键英文按钮。GitHub 上传与 Sepolia 部署请阅读单独的《上传指南》。这是使用文档，不是课程报告。

## 01 / 先选正确的文件

- StepFund-Windows.zip：Windows x64 一键运行包，内含 Node.js 与编译后的网页，不需要先安装开发工具。
- StepFund-Source.zip：完整源代码，含 Solidity、Circom、Hardhat 测试、前端、部署脚本、CI 和安全分析，供开发者修改、测试和发布。
- StepFund-使用指南.pdf：本文件，说明运行方式与功能操作。
- StepFund-GitHub与Sepolia上传指南.pdf：由接收方本人上传 GitHub、部署与验证合约的操作步骤。

## 第一次运行

1. 完整解压 StepFund-Windows.zip，保留整个文件夹结构。
2. 双击 Start StepFund.cmd，等待启动检查完成，浏览器自动打开程序。
3. 如浏览器没有打开，手动访问启动窗口显示的地址，通常是 http://127.0.0.1:5280。
4. 点击右上角“中文”切换语言。关闭启动窗口会停止服务，下次仍用同一启动文件打开。

演示模式不需要钱包或联网。端口被其他程序占用时，启动器自动选择其他端口；不同端口的浏览器数据互相独立，不代表旧数据被删除。双击 Open Startup Logs.cmd 查看启动日志。

## 02 / 演示模式与链上模式

演示模式（Practice）：数据保存在当前浏览器，可切换 Alex、Morgan 等角色，推进一天、重置演示，学习出资、投票、退款流程。它不发送区块链交易，也不生成假的链上交易哈希。

链上模式（Chain）：连接 Hardhat 本地链或 Sepolia 测试网，读取真实合约状态，每次写入都需要钱包确认。不同电脑连接同一网络、同一工厂地址，才能操作同一组项目。

DeFi 资金策略与 ZK 隐私验收必须在 v3 链上模式中运行。本地 Hardhat 也可运行真实合约、生成和验证真实证明；演示模式不会把这些操作模拟成成功的链上证明。

## 连接钱包

1. 打开“连接钱包”（Connect wallet），选择手机钱包扫码或浏览器钱包。
2. 手机 MetaMask 使用 Sepolia；Hardhat 本地链使用电脑浏览器钱包。手机中的 127.0.0.1 不是你的电脑。
3. 选择正确网络，导入发布者提供的连接 JSON，或输入工厂合约地址。
4. 在钱包确认连接，核对程序显示的账户、网络和代币。
5. 领取测试 ETH 支付手续费，再领取项目所用的测试代币。ETH 与 tUSD 是不同资产。

自带 TestUSD 有每地址每 24 小时一次的水龙头。使用 Aave 支持的外部测试资产时，需到对应发行方领取；程序会显示链上读取的资产符号。程序不支持以太坊主网。

普通使用者不需要 Etherscan API Key、GitHub 账号或开发环境。钱包授权、验证码、领取测试 ETH 等步骤由本人完成，不能由程序伪造或跳过。

## 03 / 创建、出资和阶段投票

1. 创建者打开“创建项目”（Create project），填写标题、说明、类别、募资期与阶段预算。每个项目支持 1 至 8 个阶段。
2. 截止天数从创建之日起计算。每阶段截止日应晚于上一截止日加投票期，并至少再留一天。创建后条款不可修改。
3. 检查项目并确认创建。项目方另缴总目标 5% 的保证金，不能用出资者的钱抵扣。
4. 支持者打开项目，查看预算、截止时间、保证金及可选资金策略后出资。总出资不能超过目标。
5. 募集达到目标后，任何人可启动项目；到期未达标则可开放退款。资金库若亏损，则取消启动并按实际可退本金退款。
6. 创建者在截止前提交成果链接和文件哈希，开启阶段投票；启用隐私验收的项目还必须先通过 ZK 流程。
7. 投票结束后点击结算；批准的阶段款项由创建者主动提取。失败阶段会终止后续阶段并开放剩余本金退款。

## 通过标准

赞成权重至少达到全部出资的 60%，并且赞成加反对的参与权重至少达到全部出资的 70%。两条同时满足，边界值算通过。分母是全部出资，不是仅参与投票的人。

例：总出资 1,000，600 赞成、100 反对、300 弃权，通过；只有 600 赞成、其余弃权，不通过。

出资者可在当前阶段开启投票前单层委托给其他地址，也可撤销。每阶段重新委托，不支持循环或转委托。退款归原出资者，不归受托人。

## 04 / 保证金、资金看板与待办

保证金退还：募资失败、无投票或参与率不足、全部阶段完成时，保证金退还项目方，由其主动领取。

保证金罚没：成果逾期未交，或者参与率达标但赞成比例不足时，保证金按原始出资比例补偿支持者。它不增加投票权重，也不是本金保险。

“资金透明”（Fund transparency）展示待批准、已批准待提取、可退款、已提取、已退款、资金库内本金、亏损或转为救济份额的本金。图表统计原始本金；保证金与收益分账显示。

“统一待办中心”（Action center）按照当前钱包显示投票、成果提交、验收确认、退款、收益或份额领取、提款、结算和资金库救济入口。区块链不会自动定时执行，截止之后仍须有人发送结算交易。

退款和提现没有人为设置的领取截止时间。金额按代币最小单位计算，最后一位合格领取者收到舍入余数；有时显示为零的领取仍用于完成份额计数。

## 一个最短的演示路线

先在演示模式查看资金看板与待办，再切换账户体验投票和退款。然后用本地链或已部署 Sepolia 项目演示：创建者缴保证金 → 支持者出资 → 提交成果 → 委托与投票 → 结算 → 提款或退款。最后再演示资金库与隐私验收两个可选模块。

钱包数量不代表人数。按资金加权仅能避免“同一笔资金拆成多个地址就多出票权”，不能阻止女巫攻击、串谋或贿赂。免费测试代币尤其不具备身份防刷能力。

## 05 / 文件、IPFS 与哈希核验

“成果附件库”（Evidence library）可以保存本地文件、预览图片和文本、下载文件，以及导出或导入含真实文件的成果 ZIP。单文件最大 20 MiB，库与成果包总量最大 100 MiB，最多 100 个文件。

保存到附件库不等于上传互联网；发送源码包也不会自动包含浏览器里保存的附件。换电脑之前请导出成果 ZIP，对方在相同项目中导入核验。

## 发布普通成果

1. 在项目附件区选择“Publish a file to IPFS”，连接已有、已开通空间的 Storacha 账号。本人完成邮箱授权。
2. 选择文件和空间，确认公开上传。程序使用返回的 CID 填入 IPFS 链接，并计算独立的 Keccak-256 哈希。
3. 创建者确认链上提交，固定本阶段主成果的链接与哈希。上传成功不代表已经提交到合约。
4. 审查人点击“从 IPFS 读取并核验”（Read from IPFS & verify），选择网关，点击 Verify & preview。
5. 下载字节与链上哈希一致才显示通过。网关错误、超时或哈希不符都不算通过。

也可以使用其他 IPFS 提供方，手动粘贴 ipfs:// 链接和文件哈希。Storacha 真实账户上传、服务配额和网关可用性需要接收方自行验收；本包不内置服务密钥或付费空间。旧文档域名目前发生服务跳转，账号不可用时优先使用替代提供方。

PNG、JPEG、GIF 和转义后的文本可在程序内预览。PDF、Office、HTML、SVG 使用下载或外部查看。哈希只能证明字节一致，不能证明内容真实或项目已完成。

## 06 / 资金库与 DeFi

创建 v3 链上项目时，可勾选“启用 ERC4626 资金库”，填入与项目代币一致的资金库地址。出资前即固定此配置，出资者应核对地址及风险。

募资期间，任何人可将最多 20% 的已募集本金存入该资金库。按钮使用 1% 最低接收份额滑点限制；保证金不参与投资，也不允许借贷杠杆。

启动或结算募集时，合约先尝试全部赎回。收益按原始出资比例归支持者，可通过“领取收益 / 救济份额”单独领取，不会被创建者当作阶段预算提走。

若赎回本金亏损，即使原募资达标也不启动项目，改为按实际回收本金退款，保证金退还项目方。若资金库拒绝赎回，交易整体回滚，可在恢复后重试。

募资截止七天后，若资金仍在库内，任何人可选择“取消并分发资金库份额”。项目永久取消，流动本金按比例退款；资金库份额另行领取。拿到份额不等于立即拿回全部本金，后续赎回仍受资金库流动性限制。

## 两种资金库不要混淆

ResearchVault：随标准部署脚本创建的研究资金库，无管理员，收益来自外部转入奖励，不是市场利息，也不承诺 APY。没有奖励转入时，收益接近零。

AaveV3Vault：实际调用配置的 Aave V3 Pool 存入与取出资产。必须使用该 Pool 支持的六位小数储备资产；自定义 TestUSD 不能存入 Aave。部署方法见上传指南。当前自动化测试使用明确标注的模拟 Aave Pool，未冒充已完成公开 Aave 测试。

领取救济份额后，可用区块浏览器的资金库 Write Contract 调用 redeem(shares, receiver, owner)，receiver 与 owner 填本人钱包。先查询 maxRedeem，份额参数用链上原始整数单位；若显示不可赎回，等待流动性恢复。不要直接把份额转给项目方。

## 07 / ZK 隐私验收与私密文件

创建项目时，勾选“每阶段均要求隐私范围证明”，指定不同于创建者的验收人地址，并约定整数上下限。在项目描述中写清指标、单位和测量方法。当前界面对所有阶段使用同一闭区间；验证器由工厂固定，不能自行替换。

## 文件处理

1. 展开“加密成果 / 打开私密文件”，生成 256 位文件加密密钥，并保存私密密钥文件。
2. 选择原始文件，程序下载 private-evidence.sfe 密文，并显示其 Keccak-256 哈希。密钥、原文件都不要公开上传。
3. 把 .sfe 密文通过 IPFS 发布；后续链上提交使用密文链接和密文哈希。
4. 审查人下载密文，填写正确文件密钥及链上密文哈希。核验与 AES-GCM 认证通过后，本机解密，可预览安全格式或下载原文。

## 指标验收

1. 创建者准备私密指标数值和随机盐值，例如指标 90、约定范围 80 至 100。盐值用程序生成，不使用容易猜到的短数字。
2. 将真实材料、指标与盐值私下给指定验收人；验收人独立核查，填写相同密文哈希、指标、盐值，点击“确认已核查成果”。
3. 创建者填写相同数据与已发布链接，点击“在本机生成证明”。WASM 与证明密钥在包内，计算在浏览器后台工作线程执行，可取消。
4. 页面显示本地验证通过，且链上验收承诺匹配后，点击“提交证明并开启投票”。钱包确认后，由合约再次验证，才开启普通支持者投票。

数值、盐值和文件密钥仅在页面内存中保留，离开面板可能丢失。请自行保存并私下传递，程序无法恢复。若另一位验收人刚完成交易，返回项目列表刷新再进入；重新填写原盐值和指标生成证明。

## 08 / 隐私边界与故障处理

ZK 证明的是“被承诺的数值落在约定范围内”，并绑定网络、项目、阶段和文件哈希。它不证明现实交付、验收人诚实或两个钱包属于不同的人；也不隐藏钱包、出资、投票及公开的上下限。因此仍保留保证金、成果审查与 60% / 70% 投票规则。

- 钱包取消：本次未得到确认的操作不会显示成成功。重新发起前先查看钱包活动。
- 交易等待过久：到“网络与演示 → 交易状态与恢复”查看回执，不要连续重复点击发送。
- 账户或网络变化：重新连接，确认目前是谁在操作哪个网络。
- 证明提交按钮不可用：检查验收人承诺、哈希、盐值、指标、阶段及网络是否一致，确认当前仍在提交期限内。
- 证明生成失败：指标须为范围内的非负整数；保持页面打开，尝试较新的桌面浏览器。
- 解密失败：先核对密文哈希和密钥；密钥丢失无法找回。不要把钱包私钥当作文件加密密钥。
- IPFS 网关失败：换网关、检查 CID，或让发布者确认已固定保存文件。网关不可用不是哈希通过。
- 旧项目看不到：核对工厂、网络和浏览器端口。本包可管理 v2 基础项目；新增功能要部署 v3，不迁移旧合约资金。

## 开发者快速启动

在源码目录打开终端，执行 npm ci，然后 npm run dev。本地链另开终端执行 npm run chain，再执行 npm run deploy:local。完整测试与发布命令在上传指南中。

本包没有自动上传 GitHub，也没有代替接收方部署 Sepolia。收到的两个 ZIP 与两份 PDF 应保持版本一致，发布后请向使用者发送新的公开连接 JSON。
